# BUG-001: Phone Number Validation Rejects Domestic Pakistani Phone Numbers

- **ID:** BUG-001
- **Severity:** P0 (Critical / Blocker)
- **Priority:** High
- **Component:** Customer Authentication (`src/Routes/customerAuth.js`, `src/models/Customer.js`)
- **Reported By:** Quality Engineering Lead
- **Status:** Verified Fixed

## 1. Description
Customer registration and login rejected valid domestic Pakistani numbers starting with `0` (e.g. `03001234567`). Customers received the error: `"Enter a valid international phone number."`

## 2. Steps to Reproduce
1. Navigate to `/customer`.
2. Select **Create Account**.
3. Enter Name: `Alice Quality`, Phone: `03001234567`, Email: `alice@example.com`, Password: `password123`.
4. Click **Create Account**.

## 3. Expected Result
Account is created successfully, user session is initialized, and dashboard is displayed.

## 4. Actual Result
Registration fails with validation error: `"Enter a valid international phone number."`

## 5. Root Cause
The backend validator and Mongoose schema used the rigid international-only regex `/^\+[1-9]\d{6,14}$/` which required a leading `+` and country code, rejecting standard 11-digit local mobile numbers.

## 6. Fix Applied
Updated `isValidPhone` utility and `Customer.js` schema regex to `/^(\+?[1-9]\d{6,14}|0\d{9,11})$/`, accepting both domestic (`03001234567`) and international (`+923001234567`) formats.

## 7. Verification
Verified via Playwright test `tests/e2e/auth.spec.js` (Test `AUT-01`).
