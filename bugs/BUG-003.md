# BUG-003: ReDoS & Regex Injection in Menu Search

- **ID:** BUG-003
- **Severity:** P0 (Critical / Blocker)
- **Priority:** High
- **Component:** Menu API (`src/Routes/menu.js`)
- **Reported By:** Security & Quality Engineering
- **Status:** Verified Fixed

## 1. Description
Passing unescaped regular expression characters (e.g. `((a+)+)+$`, `.*`, `^`) in `GET /api/menu?search=...` caused catastrophic backtracking and allowed unauthorized query modification.

## 2. Steps to Reproduce
1. Execute `curl "http://localhost:3000/api/menu?search=((a%2B)%2B)%2B%24"`.
2. Notice excessive CPU consumption and thread blockage.

## 3. Expected Result
Regex special characters are escaped as literal search strings, completing safely in < 20ms.

## 4. Actual Result
Unsanitized string passed directly to `new RegExp(req.query.search, 'i')`.

## 5. Fix Applied
Sanitized `search` using `escapeRegex(search)` before constructing the MongoDB `$regex` query filter.

## 6. Verification
Verified via `tests/security/security.spec.js` (Test `SEC-05: Sanitize search inputs against ReDoS attack vectors`).
