# RCA-004: Guest Reservation Data Linkage Failure on User Registration (5-Why Analysis)

**Incident / Defect:** Guest reservations orphaned with `customerId: null` upon account creation.  
**Severity:** P0 (Blocker)  
**Impact:** Customers unable to view, manage, or cancel reservations booked as guests after creating an account.  
**Author:** Lead Systems Architect & Quality Engineer  

---

## 1. Incident Overview
When an anonymous guest books a table and later registers an account using the same phone number, the customer portal displayed "No reservation requests yet."

---

## 2. 5-Why Root Cause Analysis

1. **Why were prior reservations missing from the customer portal?**  
   Because the query `GET /api/reservations/mine/list` filters strictly by `customerId: req.customer._id`.

2. **Why was `customerId` not set on the earlier reservations?**  
   Because they were created anonymously before the customer had a user account.

3. **Why were they not updated when the account was created?**  
   Because the user registration handler only inserted a new `Customer` record without reconciling existing unlinked guest documents.

4. **Why was automatic reconciliation omitted?**  
   Because user registration and reservation management were built as isolated micro-modules without an event listener or cross-entity reconciliation workflow.

5. **Why was this missed during integration testing?**  
   Because test cases tested registration and reservations in separate, non-overlapping user sessions without testing the guest-to-customer conversion lifecycle.

---

## 3. Corrective & Preventive Actions (CAPA)

- **Immediate Fix:** Built `claimGuestReservations(customerId, phone)` triggered upon both registration and login.
- **Automated Verification:** Added API integration test in `tests/api/api-runner.js` verifying customer claim logic.
- **Testing Standard:** Added multi-stage user journey scenarios to the E2E test plan.
