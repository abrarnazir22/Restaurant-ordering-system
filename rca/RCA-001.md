# RCA-001: Phone Number Validation Logic Failure (5-Why Analysis)

**Incident / Defect:** Domestic phone numbers rejected during customer registration and login.  
**Severity:** P0 (Blocker)  
**Impact:** 100% of customers attempting to register with local domestic phone numbers (`03001234567`) were blocked from creating accounts.  
**Author:** Lead Systems Architect & Quality Engineer  

---

## 1. Incident Overview
During customer portal onboarding testing, valid local 11-digit phone numbers were consistently rejected with the error `"Enter a valid international phone number."`

---

## 2. 5-Why Root Cause Analysis

1. **Why was the user unable to register an account?**  
   Because the registration request was rejected by the backend with an HTTP 400 validation error.

2. **Why was the request rejected with an HTTP 400 validation error?**  
   Because the `isValidPhone` function returned `false` for the input `03001234567`.

3. **Why did `isValidPhone` return `false` for a standard mobile number?**  
   Because it evaluated the input against a strict international regex `/^\+[1-9]\d{6,14}$/`.

4. **Why did the regex strictly mandate a leading `+` and country code?**  
   Because the regex was copied from an international specification library without tailoring for domestic market standards where consumers input local `03XX` prefix numbers.

5. **Why was this mismatch not caught prior to implementation?**  
   Because input validation requirements were not grounded in local market user personas, and automated boundary tests for domestic phone formats were missing from the initial test suite.

---

## 3. Corrective & Preventive Actions (CAPA)

- **Immediate Fix:** Updated `isValidPhone` and Mongoose schema to `/^(\+?[1-9]\d{6,14}|0\d{9,11})$/`, accommodating domestic 11-digit and E.164 international numbers.
- **Automated Verification:** Added Playwright end-to-end tests (`tests/e2e/auth.spec.js` - `AUT-01` and `AUT-02`) and API boundary assertions.
- **Policy Change:** Implemented mandatory local format test fixtures in all user onboarding validation test matrices.
