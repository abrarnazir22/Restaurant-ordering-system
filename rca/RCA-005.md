# RCA-005: Memory Map Iteration Crash in Product Recommendations (5-Why Analysis)

**Incident / Defect:** `GET /api/recommendations/:id` crashed with HTTP 500 TypeError.  
**Severity:** P0 (Blocker)  
**Impact:** 100% failure rate on recommendations queries, breaking the "Frequently paired items" modal.  
**Author:** Lead Systems Architect & Quality Engineer  

---

## 1. Incident Overview
When requesting pairing recommendations for a menu item, the backend threw an unhandled exception: `TypeError: ... .entries is not a function`.

---

## 2. 5-Why Root Cause Analysis

1. **Why did the recommendation endpoint return HTTP 500?**  
   Because an unhandled TypeError halted request processing.

2. **Why was a TypeError thrown during execution?**  
   Because the code attempted to call `.entries()` on an Object that did not possess that method.

3. **Why did the Object lack the `.entries()` method?**  
   Because the data was retrieved as a plain JSON dictionary object rather than an instantiated Mongoose Map instance.

4. **Why was the type polymorphic and unexpected?**  
   Because depending on whether the data came from active Mongoose documents or cached plain JSON objects, the container type differed.

5. **Why was type safety not guaranteed?**  
   Because dynamic JavaScript duck typing was used without runtime type assertions or fallback handlers for plain dictionary objects.

---

## 3. Corrective & Preventive Actions (CAPA)

- **Immediate Fix:** Refactored iterator to evaluate `items instanceof Map ? Array.from(items.entries()) : Object.entries(items || {})`.
- **Automated Verification:** Added Category 4 in `tests/api/api-runner.js` validating recommendation responses.
- **Coding Standard:** Added defensive type validation rules for all collection-like structures.
