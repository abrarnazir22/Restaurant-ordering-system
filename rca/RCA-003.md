# RCA-003: ReDoS & Regex Injection in Menu Search Endpoint (5-Why Analysis)

**Incident / Defect:** Regular Expression Denial of Service vulnerability in menu search.  
**Severity:** P0 (Blocker)  
**Impact:** Node.js event loop freezes for several seconds upon processing malicious search parameters, causing complete service degradation.  
**Author:** Security & Quality Engineering Lead  

---

## 1. Incident Overview
Sending nested quantifier regex payloads (e.g. `((a+)+)+$`) in query parameters caused 100% CPU utilization and blocked all concurrent Express request processing.

---

## 2. 5-Why Root Cause Analysis

1. **Why did the server freeze when searching for certain keywords?**  
   Because the V8 JavaScript engine experienced catastrophic backtracking in its regular expression engine.

2. **Why did the regex engine encounter catastrophic backtracking?**  
   Because user-supplied search strings were passed raw into `new RegExp(req.query.search, 'i')`.

3. **Why were user strings passed unescaped into `new RegExp`?**  
   Because the developer attempted to implement case-insensitive substring searching without sanitizing regex meta-characters (`+`, `*`, `(`, `)`, `$`, `^`).

4. **Why was regex used instead of standard substring or text index matching?**  
   Because ad-hoc regex querying was the fastest implementation path compared to configuring a MongoDB text index or escaped pattern.

5. **Why was this vulnerability not detected during development?**  
   Because security-focused automated negative testing was not integrated into the automated test pipeline.

---

## 3. Corrective & Preventive Actions (CAPA)

- **Immediate Fix:** Created `escapeRegex(string)` utility replacing meta-characters with literal escape sequences before passing to Mongoose queries.
- **Automated Verification:** Added dedicated automated test `SEC-05` in `tests/security/security.spec.js`.
- **Security Policy:** Added mandatory input sanitization checklist to PR review templates.
